# Benchmark

Generated by `go run ./benchmark` on 2026-11-21, linux/amd64, 8 CPUs. Each suite runs
3 times on parallel machines: real pytest processes, one per machine, driven
by the real `bunpo` binary. The first run has no timing history, so files are
dealt out evenly; later runs use the merged timings.

- **Predicted** is the sum of the recorded medians for a machine's files.
- **Tests** is the time pytest reported for those files.
- **Wall** is the whole pytest process, including its setup. On this machine,
  pytest with one empty test takes 134 ms, the fixed cost on every machine.

The ratio is slowest over fastest among machines with files. PROJECT.md
requires a predicted ratio of at most 1.10 on its declared benchmark, here
the Many files suite. It is a target for that benchmark, not a promise for
every suite: the Tight suite below shows where longest-first dealing falls
short.

## Large suite CLI timing (50,000 tests, 256 machines)

Measured end-to-end by generating 50,000 canonical test file paths with a
matching `.bunpo/timings.json`, piping the full list into
`bunpo split --index 0 --total 256 --dir <tmp> >/dev/null`, and timing the
whole process (startup, JSON decode, canonicalization, LPT split, SHA-256
digest, stdout write, and atomic manifest write):

- **`v0.1.0` full CLI:** 0.16 to 0.26 s (0.185 to 0.264 s on Intel Core Ultra 9 288V, 8 cores; an independent run measured 0.20 to 0.25 s).
- **`v0.0.7` full CLI (same machine):** 0.213 to 0.285 s.

All runs are well under the 1-second budget in `PROJECT.md`.
